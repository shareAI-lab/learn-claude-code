2025 年是 AI 编码工具爆发的一年——Claude Code、Codex CLI、Cursor、Aider……你可能已经用不过来了。

但有个项目在 GitHub 上默默涨到了 6 万+ star，社区里有人叫它"AI 编码界的 Neovim"。

它叫 Pi。

● ● ●

Pi 是什么

一句话：Pi 是一个用 TypeScript 写的、极简的、开源的终端编码 Agent Harness。

关键词拆解：

  •  极简：核心只有 4 个工具——read、write、edit、bash。没有 plan mode，没有 sub-agent，没有 todo list，没有权限弹窗
  •  开源：MIT License，代码完全透明
  •  终端：纯 CLI，不依赖 IDE，tmux / Neovim 用户友好
  •  Agent Harness：它的定位不是"AI 模型"，而是"让模型能干活的框架"——模型负责决策，Pi 负责执行
  •  模型无关：支持 Anthropic、OpenAI、Google、DeepSeek、Mistral、Groq、Ollama 等 15+ Provider

作者是 Mario Zechner（libGDX 框架的创建者），2026 年 4 月加入 Earendil Inc. 继续开发 Pi。

如果你用过 Claude Code，理解 Pi 最快的方式是：Pi 是 Claude Code 去掉所有"帮你做决定"的功能后的版本。 它把控制权完全交还给你。

各自适合谁？

Claude Code：开箱即用，功能最全，Terminal-Bench 2.0 跑 92.1%。适合不想折腾、追求最大生产力的开发者。缺点是模型锁定 Anthropic、闭源、系统提示词 14000 token 偏重。

Codex CLI：ChatGPT Plus 用户免费可用，Terminal-Bench 2.0 跑 77.3%。适合已经在 OpenAI 生态里、想试试 CLI Agent 的开发者。缺点是模型锁定 OpenAI、agentic 能力不如 Claude Code。

OpenClaw：Peter Steinberger 开源（原名 Clawdbot），60 天从 9K 涨到 188K stars——GitHub 增长最快的 repo 之一。和编码 Agent 不同，它的定位是全能 Agent 网关：接 50+ 消息平台（微信、飞书、Slack、Discord、Telegram…），100% 本地运行，支持 Claude/GPT/Gemini/DeepSeek/Ollama 等模型。适合需要跨平台自动化、不只是写代码的场景。

QwenPaw（通义爪）：阿里 AgentScope 团队出品，v2.0 基于 Agent OS 架构重写。和 OpenClaw 类似接消息平台（钉钉/飞书/微信/Discord），但更偏中国生态，内置 ReMe 长期记忆、Scroll Context、Oh-My-Paw 插件市场。适合国内开发者想要一个接钉钉飞书的个人 AI 助手。

Hermes：两条线。一个是 Hermes IDE（AI 原生终端 + IDE，多 Agent 并行 + Git worktree 隔离），适合想要 IDE 级体验但不想用 Cursor 的开发者。另一个是 NousResearch 的 Hermes Agent——一个可扩展的通用 Agent 框架，支持 Skill、Cron 定时、跨平台消息投递。

Pi：极简、透明、模型无关。适合——

Pi 适合想要完全控制权的开发者：你知道自己在做什么，不需要 Agent 替你做决定，你要的是一个可靠、可审计、可定制的执行框架。

Pi 的核心设计哲学

1. 少即是多

Pi 的系统提示词只有 ~1000 token。Claude Code 是 14000 token——差了 14 倍。

这意味着什么？每次调用模型，Pi 的 token 开销远低于 Claude Code。长对话场景下，这个差距会累积成真金白银。

2. 模型无关

Pi 不绑定任何模型厂商。你可以早上用 Claude 写复杂逻辑，下午切到 DeepSeek 做批量任务，晚上用本地 Ollama 做实验——同一个 Agent，同一个配置，只切模型。

配置方式：

# API Key 方式（支持 15+ Provider）
export ANTHROPIC_API_KEY=sk-ant-...
# 或
export OPENAI_API_KEY=sk-...
# 或
export DEEPSEEK_API_KEY=...
# 或本地模型
# 在 ~/.pi/agent/models.json 配置 Ollama
 

3. 没有权限系统——但有容器隔离

Pi 默认以你的用户权限运行，不弹权限确认框。这可能让习惯 Claude Code 审批弹窗的人不安。

Pi 的官方态度是：如果你需要安全边界，用容器隔离，而不是弹窗确认。

三种容器化方案：

方案隔离范围适用场景
Gondolin 扩展内置工具路由进 micro-VM本地开发，auth 留在宿主机
Plain Docker整个 pi 进程简单隔离
OpenShell策略控制的沙箱企业级托管

4. JSONL 会话树——不可篡改的事实日志

Pi 把每次对话存成 JSONL 格式的会话树。每条消息带父指针，可以分支、恢复、审计。

换行是 commit marker：半行 JSON 不算事实。 这个设计保证了即使进程崩溃，已落盘的对话不会损坏。

5. TypeScript 类型安全

Pi 用 TypeScript 写的，从协议层到工具层都有严格的类型约束。少写一个 case 编译就报错——类型系统替你守住了不变量。

Pi 的配套生态

Pi 不是一个人在战斗，它有完整的包体系：

包作用
@earendil-works/pi-ai统一多 Provider LLM API（OpenAI、Anthropic、Google 等）
@earendil-works/pi-agent-coreAgent 运行时（工具调用 + 状态管理）
@earendil-works/pi-coding-agent编码 Agent CLI（read/write/edit/bash）
@earendil-works/pi-tui终端 UI 库（差分渲染）
pi-chatSlack/聊天自动化扩展

Skill 生态

Pi 实现了 Agent Skills 标准，可以直接加载 Claude Code 和 Codex 的 Skill：

// ~/.pi/agent/settings.json
{
  "skills": [
    "~/.claude/skills",
    "~/.codex/skills"
  ]
}

你在 Claude Code 里积累的 Skill 可以直接在 Pi 里用，不用重写。

Extension 扩展

Pi 的 Extension 是 TypeScript 模块，能力很强：

  •  自定义工具（LLM 可调用）
  •  事件拦截（工具调用前/后、会话、模型）
  •  自定义命令和 UI 组件
  •  会话持久化（跨重启存状态）

社区已有 Git checkpoint、权限门、路径保护、自定义压缩等扩展。

实际生产中的配置

快速开始

# 安装
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
 
# 认证（三种方式任选）
# 方式1：订阅登录（Claude Pro/Max、ChatGPT Plus、GitHub Copilot）
pi
> /login
 
# 方式2：API Key
export ANTHROPIC_API_KEY=sk-ant-...
pi
 
# 方式3：本地模型（Ollama）
# 在 ~/.pi/agent/models.json 配置
 

项目配置

Pi 在项目目录下加载这些文件：

文件作用加载时机
AGENTS.md项目指令（Pi 版 CLAUDE.md）启动自动加载
.pi/settings.json项目级设置需要信任确认
.pi/skills/项目级 Skill需要信任确认
.pi/extensions/项目级扩展需要信任确认
.pi/prompts/提示词模板需要信任确认

AGENTS.md 示例：

# 项目指令
 
技术栈：TypeScript + React + Vite
测试：npm test
构建：npm run build
代码风格：biome 格式化
 
规则：
- 改完代码必须跑 npm run check
- 不要碰 src/generated/ 目录
- 函数必须有返回类型标注
 

全局设置

~/.pi/agent/settings.json 管全局配置：

默认模型：defaultModel
思考深度：defaultThinkingLevel（off/minimal/low/medium/high/max）
缓存提示：showCacheMissNotices（显示 prompt cache miss）
思考预算：thinkingBudgets（每个 level 的 token 预算）
 

本地模型配置

用 Ollama 或 vLLM 跑本地模型：

~/.pi/agent/models.json
 
配置 provider（baseUrl + api + models）
支持 OpenAI 兼容和 Anthropic 兼容两种 API 格式
可以覆盖内置 Provider 的模型配置

Pi 适合谁，不适合谁

适合 Pi 的场景

  •  你想完全控制 Agent 的行为，不需要它替你做决定
  •  你需要模型灵活性——在不同 Provider 之间切换
  •  你是 tmux / Neovim / 终端重度用户
  •  你关注 token 成本——1000 token 系统提示词 vs 14000 token
  •  你想读源码学习 Agent 架构（MIT 开源 + TypeScript 类型安全）
  •  你有自己的安全策略（容器、沙箱），不需要弹窗审批

不适合 Pi 的场景

  •  你要开箱即用的最完整体验 → 用 Claude Code
  •  你需要 sub-agent、plan mode、todo list 等内置功能 → 用 Claude Code
  •  你不想管安全策略，需要 Agent 自己审批 → 用 Claude Code
  •  你只用 ChatGPT Plus，不想额外付费 → 用 Codex CLI
  •  你要接消息平台做自动化助手 → 用 OpenClaw 或 QwenPaw
  •  你要 IDE 级的 Agent 体验 → 用 Hermes IDE 或 Cursor

一句话：Claude Code 是"帮你做决定"的 Agent，Pi 是"你自己做决定"的 Harness。
