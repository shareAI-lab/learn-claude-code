我以前以为并行改代码最怕某个 Agent 失败。s18 给了一个更糟的场景：Alice 和 Bob 都成功写完 config.py，只是 Bob 最后保存，于是 Alice 的结果安静地消失了。

上一节 s17 已经让队友自己看任务板：schema 给 Alice，API 给 Bob，owner 和状态都分得清。可任务所有权只回答“谁负责”，工具仍然在同一个 WORKDIR 里执行。

所以 s18 继续把“任务分开”推进到“目录分开”：每个任务可绑定一个 Git worktree，也就是同一仓库的另一份工作目录和另一条分支；Agent 的 bash/read/write 真正在那个目录运行。

并行隔离不能靠提示词说“别碰别人的文件”，要让两个 Agent 的工具根本落在不同目录。

● ● ●

owner 分开了，文件为什么还会互相覆盖

s17 的任务文件大概是这样：

{
  "subject": "edit auth config",
  "status": "in_progress",
  "owner": "alice"
}

它能阻止 Bob 再认领同一任务，却不能阻止 Bob 的另一个任务也写 config.py。因为 s17 的工具都固定使用主仓库：

# s17 所有队友都固定在主仓库目录执行
subprocess.run(command, cwd=WORKDIR, ...)

s18 给 Task 增加 worktree，再把工具当前目录跟任务绑定：

维度s17s18
任务归属ownerowner 保留
工作目录所有队友共享 WORKDIR任务可绑定独立 worktree
Git 分支共享当前分支每个 worktree 使用 wt/
工具执行bash/read/write 固定主目录wrapper 读取队友自己的 wt_ctx
收尾只完成任务keep 或检查后 remove
记录任务 JSON再加 .worktrees/events.jsonl

worktree 先用人话解释：它让一个 Git 仓库同时展开成多个目录，每个目录检出自己的分支，但底层对象仍由同一个仓库管理。不用复制整个 .git，也不用让两个 Agent 抢一个工作区。

并行先发生覆盖事故

● ● ●

第一块：任务只多一个 worktree 字段

s18 没重写任务系统，只给数据结构补一项：

@dataclass
class Task:
    id: str
    subject: str
    description: str
    status: str
    owner: str | None
    blockedBy: list[str]
    # s18 只新增这一项：绑定的 worktree 名字
    # s18: bound worktree name
    worktree: str | None = None

这里存的是名字，例如 alice-config，不是任意绝对路径。真实目录统一由：

WORKTREES_DIR = WORKDIR / ".worktrees"
                            # 所有 worktree 统一放在主仓库的 .worktrees 下

计算为 .worktrees/alice-config。

任务记录“我要去哪做”，队友线程记录“我现在正在哪做”。前者是持久化的 task.worktree，后者是内存里的 wt_ctx，两者后面会在认领时接起来。

绑定函数故意只改 worktree，不改状态：

def bind_task_to_worktree(task_id: str, worktree_name: str):
    """Write worktree field to task. Keep status as pending for auto-claim."""
    # 重新加载任务
    task = load_task(task_id)
    # 只改 worktree 字段
    task.worktree = worktree_name
    # 落盘
    save_task(task)
    print(f"  \033[33m[bind] {task.subject} → worktree:{worktree_name}\033[0m")

这点很关键。Lead 可以提前建好任务和目录，任务仍保持 pending；真正有队友认领时，才走 pending → in_progress。

绑定目录不是认领任务，两种状态不能顺手混在一起。

任务管目标目录管边界

● ● ●

第二块：目录名先校验，再交给 Git

worktree 名字最终会进入文件路径和 Git 分支名，不能直接相信模型输出。s18 先做白名单校验：

VALID_WT_NAME = re.compile(r'^[A-Za-z0-9._-]{1,64}$')
                  # 名字白名单：字母、数字、点、下划线、连字符，最长 64


def validate_worktree_name(name: str) -> str | None:
    """Return error message if invalid, None if valid."""
    # 不能为空
    if not name:
        return "Worktree name cannot be empty"
    # 明确拒绝目录穿越名
    if name == "." or name == "..":
        return f"'{name}' is not a valid worktree name"
    # 必须匹配白名单正则
    if not VALID_WT_NAME.match(name):
        return (f"Invalid worktree name '{name}': "
                "only letters, digits, dots, underscores, dashes (1-64 chars)")
    return None

规则很朴素：

  •  不能为空。
  •  明确拒绝 . 和 ..。
  •  只允许字母、数字、点、下划线、连字符。
  •  最长 64 个字符。

路径隔离的第一步，是不让名字逃出预定目录。像 ../../main、auth/new、带空格或 shell 特殊字符的字符串都会被拒绝。

这里不用 shell 拼接 Git 命令。run_git() 传入参数数组：

def run_git(args: list[str]) -> tuple[bool, str]:
    """Run git command. Return (ok, output)."""
    try:
        # 参数数组传入，不用 shell 拼接
        r = subprocess.run(["git"] + args, cwd=WORKDIR,
                           capture_output=True, text=True, timeout=30)
        # 合并 stdout 和 stderr
        out = (r.stdout + r.stderr).strip()
        out = out[:5000] if out else "(no output)"
        # 同时返回成功标志和文本
        return r.returncode == 0, out
    except subprocess.TimeoutExpired:
        return False, "Error: git timeout"

没有 shell=True，校验过的名字作为一个独立参数交给 Git；返回值同时带 ok 和文本，调用方可以只在成功后写事件日志。

● ● ●

第三块：创建目录、分支，再绑定任务

核心入口 create_worktree() 做四件事：

def create_worktree(name: str, task_id: str = "") -> str:
    """Create a git worktree with a dedicated branch. Optionally bind to a task."""
    # ① 先校验名字
    err = validate_worktree_name(name)
    if err:
        return f"Error: {err}"
    # ② 计算目录路径
    path = WORKTREES_DIR / name
    if path.exists():
        return f"Worktree '{name}' already exists at {path}"
    # ③ Git 从当前 HEAD 建新分支 wt/<name> 和新目录
    ok, result = run_git(["worktree", "add", str(path), "-b", f"wt/{name}", "HEAD"])
    if not ok:
        return f"Git error: {result}"
    if task_id:
        # ④ Git 成功后才绑定任务
        bind_task_to_worktree(task_id, name)
    # ⑤ 记录 create 事件
    log_event("create", name, task_id)
    print(f"  \033[33m[worktree] created: {name} at {path}\033[0m")
    return f"Worktree '{name}' created at {path}"

按执行顺序读：

  1. 01validate_worktree_name() 拦截危险名字。
  2. 02如果 .worktrees/ 已存在，直接返回，不覆盖。
  3. 03Git 执行 worktree add -b wt/ HEAD：从当前 HEAD 建新分支和新目录。
  4. 04Git 成功后，若传了 task_id，才调用 bind_task_to_worktree()。
  5. 05最后记录 create 事件并打印路径。

只有 Git 真创建成功，任务才会绑定、事件才会落盘。如果 Git 命令失败，任务仍保持原样，日志也不会假装创建成功。

不过这里有一个补偿问题：Git 成功后，如果 task_id 不存在，bind_task_to_worktree() 会抛错，已经创建的 worktree 不会自动删除。教学版没有事务回滚，这也是可以继续补的边界。

● ● ●

第四块：认领后，工具 cwd 才真正切过去

光把路径写进任务文件还不够。bash/read/write 必须真的用它。

队友线程内部维护一份自己的当前目录：

# Track current worktree for this teammate's cwd
# 队友线程内部维护一份自己的当前目录（用 dict 方便多处共享修改）
wt_ctx = {"path": None}


def _wt_cwd() -> Path | None:
    # 取当前 cwd，没绑定则返回 None
    p = wt_ctx["path"]
    return Path(p) if p else None


def _run_bash(command: str) -> str:
    # bash 工具的 wrapper：把 wt_ctx 作为 cwd
    return run_bash(command, cwd=_wt_cwd())


def _run_read(path: str) -> str:
    # read 工具的 wrapper：相对路径在 worktree 内解析
    return run_read(path, cwd=_wt_cwd())


def _run_write(path: str, content: str) -> str:
    # write 工具的 wrapper：写入文件也落在 worktree 目录
    return run_write(path, content, cwd=_wt_cwd())

wt_ctx 用 dict 而不是一个普通局部字符串，是为了让多个内层函数共享并修改同一份引用。

这里的 cwd 是 current working directory，也就是命令和相对路径从哪里开始算。当 wt_ctx["path"] 是 Alice 的 worktree，write_file("config.py") 就会写到 .worktrees/alice-config/config.py，不是主仓库的 config.py。

手动调用队友工具 claim_task 时，路径这样更新：

def _run_claim_task(task_id: str):
    # 先走 s17 真实认领逻辑
    result = claim_task(task_id, owner=name)
    if "Claimed" in result:
        # Set worktree cwd if task has one
        # 只有成功才重新读任务取 worktree
        task = load_task(task_id)
        if task.worktree:
            # 有绑定就把当前 cwd 切到该 worktree
            wt_ctx["path"] = str(WORKTREES_DIR / task.worktree)
        else:
            # 没绑定就明确清空，回到主目录
            wt_ctx["path"] = None
    return result

逐行看：

  •  先走 s17 的真实认领逻辑，写 owner 和 in_progress。
  •  只有返回 Claimed 才继续，失败不能乱切目录。
  •  重新读任务，取最新的 task.worktree。
  •  有绑定就更新 wt_ctx，没绑定就明确清空，回到主目录。

完成任务时又会清空：

def _run_complete_task(task_id: str):
    # 完成任务
    result = complete_task(task_id)
    # 完成后清空当前 cwd（无论成功与否）
    wt_ctx["path"] = None
    return result

这里还有一个小缺口：即使 complete_task() 返回失败，wt_ctx 也会被清空。更稳妥的写法应只在完成成功后清空。

工具cwd跟着切换

● ● ●

safe_path() 也跟着 cwd 改了

相对路径换了根目录，路径安全检查也必须换根：

def safe_path(p: str, cwd: Path = None) -> Path:
    # base 跟随当前 cwd，不再固定主仓库
    base = cwd or WORKDIR
    path = (base / p).resolve()
    # 解析后必须仍在 base 范围内
    if not path.is_relative_to(base):
        raise ValueError(f"Path escapes workspace: {p}")
    return path

s17 只检查路径不能逃出 WORKDIR；s18 改成不能逃出当前 base。当 base 是 Alice 的 worktree 时，../bob/config.py 解析后不再属于 Alice 的目录，会被拒绝。

目录切换和路径校验必须一起改。 如果工具在 worktree 运行，但 safe_path 仍只校验主仓库范围，Alice 仍可能用 ../ 写到别人的目录，隔离就只剩一半。

run_bash() 也接受 cwd：

def run_bash(command: str, cwd: Path = None) -> str:
    try:
        # cwd 为空时才用主仓库
        r = subprocess.run(command, shell=True, cwd=cwd or WORKDIR,
                           capture_output=True, text=True, timeout=120)
        out = (r.stdout + r.stderr).strip()
        return out[:50000] if out else "(no output)"
    except subprocess.TimeoutExpired:
        return "Error: Timeout (120s)"

这保证 git status、测试命令、构建命令都从绑定分支的目录执行，不只是 read/write 换路径。

● ● ●

收尾不能一删了之

任务完成后，Lead 可以保留 worktree 供人工 review，也可以删除。但默认删除前要检查现场：

def remove_worktree(name: str, discard_changes: bool = False) -> str:
    """Remove worktree. Refuses if uncommitted changes unless discard_changes."""
    # ① 名字仍要校验
    err = validate_worktree_name(name)
    if err:
        return err
    # ② 目录必须存在
    path = WORKTREES_DIR / name
    if not path.exists():
        return f"Worktree '{name}' not found"
    if not discard_changes:
        # ③ 统计未提交文件与未推送提交
        files, commits = _count_worktree_changes(path)
        if files < 0:
            # 无法判定状态时拒绝删除
            return (f"Cannot verify worktree '{name}' status. "
                    "Use discard_changes=true to force removal.")
        if files > 0 or commits > 0:
            # 有任何成果就拒绝，提示强制丢弃或保留
            return (f"Worktree '{name}' has {files} uncommitted file(s) "
                    f"and {commits} unpushed commit(s). "
                    "Use discard_changes=true to force removal, "
                    "or keep_worktree to preserve for review.")
    # ④ 确认干净后删目录
    ok1, _ = run_git(["worktree", "remove", str(path), "--force"])
    if not ok1:
        return f"Failed to remove worktree directory for '{name}'"
    # ⑤ 再删分支
    run_git(["branch", "-D", f"wt/{name}"])
    # ⑥ 记 remove 事件
    log_event("remove", name)
    return f"Worktree '{name}' removed"

默认路径是：

  1. 01名字仍要校验。
  2. 02目录必须存在。
  3. 03没有 discard_changes=True 时，统计未提交文件与未推送提交。
  4. 04有任何成果就拒绝删除，提示强制丢弃或 keep。
  5. 05确认干净后，删除 worktree，再删 wt/ 分支。
  6. 06成功后写 remove 事件。

keep_worktree() 则只记一条事件，保留目录和分支：

def keep_worktree(name: str) -> str:
    """Keep worktree for manual review. Branch preserved."""
    # 名字仍要校验
    err = validate_worktree_name(name)
    if err:
        return err
    # 只记一条事件，保留目录和分支
    log_event("keep", name)
    print(f"  \033[36m[worktree] kept: {name}\033[0m")
    return f"Worktree '{name}' kept for review (branch: wt/{name})"

有改动时默认保留，是比“任务做完自动清目录”更安全的默认值。

事件日志写到 .worktrees/events.jsonl：

def log_event(event_type: str, worktree_name: str, task_id: str = ""):
    # 把一条事件追加到 .worktrees/events.jsonl
    event = {"type": event_type, "worktree": worktree_name,
             "task_id": task_id, "ts": time.time()}
    events_file = WORKTREES_DIR / "events.jsonl"
    with open(events_file, "a") as f:
        f.write(json.dumps(event) + "\n")

它能回答何时 create/keep/remove，但还不是完整恢复索引。进程重启后若要恢复全部状态，仍要扫描 git worktree list、任务文件和事件日志。

三条关键线：

  •  Lead → worktree + 任务板：一次建好分支、目录和任务绑定，不逐个指挥
  •  队友 → wt_ctx：认领时把 task.worktree 复制到自己的当前目录，之后所有工具都走这个目录
  •  完成 → 检查现场：有未提交改动就保留，没改动才删

隔离不是靠"提醒大家别碰别人文件"，而是让两个 Agent 的 bash/read/write 根本落在不同目录。

● ● ●

把任务、分支、工具串成完整链路

把前面的代码合起来，一次隔离执行应该这样走：

Lead 创建 task：edit config（pending）
  ↓
create_worktree("alice-config", task_id)
  ① 校验名字
  ② git worktree add .worktrees/alice-config
       -b wt/alice-config HEAD
  ③ task.worktree = "alice-config"
  ④ task 仍是 pending
  ↓
Alice 认领任务
  ⑤ claim_task：owner=alice，status=in_progress
  ⑥ _run_claim_task 读取 task.worktree
  ⑦ wt_ctx.path = .worktrees/alice-config
  ↓
Alice 调 bash/read/write
  ⑧ wrapper 把 wt_ctx 作为 cwd
  ⑨ 相对路径只在 Alice worktree 内解析
  ↓
完成任务
  ⑩ complete_task → completed
  ⑪ wt_ctx 清空
  ↓
Lead 检查现场
  ⑫ dirty / 未推送 → keep
  ⑬ 确认干净或明确 discard → remove

这里最关键的两处不是 Git 命令本身，而是绑定时不提前改任务状态，以及认领成功后把持久化的 task.worktree 复制到线程当前 cwd。

Demo：跑一遍看隔离目录怎么工作

光看代码没感觉，跑一下。

先创建一个任务，再给它分配一个独立 worktree：

s18 >> Create task + isolated worktree for alice
  [bind] edit config → worktree:alice-config
  [worktree] created: alice-config at .../.worktrees/alice-config

[bind] 说明任务和目录已经绑定：task.worktree = "alice-config"。但注意此时任务状态还是 pending——绑定目录不等于自动认领，两件事是分开的。

看一下 Git 里的状态：

git branch: wt/alice-config
git status: ?? config.py

分支是 wt/alice-config，不是主分支。Alice 在这里改文件，不会碰到主目录或其他队友的代码。?? config.py 表示有一个新文件还没提交——这就是"脏文件"。

现在试着删除这个 worktree：

 remove without discard: Worktree 'alice-config' has 1 uncommitted file(s) and 0 unpushed commit(s). Use discard_changes=true to force removal, or keep_worktree to preserve for review.

有未提交文件，remove_worktree() 拒绝删除。除非明确传 discard_changes=true，否则代码宁可保留也不丢成果。这是比"做完自动删目录"更安全的默认值。

那就保留：

  [worktree] kept: alice-config
 keep: Worktree 'alice-config' kept for review (branch: wt/alice-config)

目录和分支都留着，等人工 review。

一句话总结：每个任务绑一个独立 Git 分支和目录，队友在里面干活互不干扰；删之前先检查有没有没提交的成果。

● ● ●

源码审计：自动认领没有更新 wt_ctx

读完整链路时，我发现 s18 最关键的缺口不在 Git，而在 s17 继承来的自动认领路径。

手动工具认领走的是队友线程里的 _run_claim_task()：

def _run_claim_task(task_id: str):
    # 手动认领走线程内的 wrapper
    result = claim_task(task_id, owner=name)
    if "Claimed" in result:
        task = load_task(task_id)
        if task.worktree:
            # 手动路径会更新 wt_ctx，切到 worktree 目录
            wt_ctx["path"] = str(WORKTREES_DIR / task.worktree)
    return result

它会更新 wt_ctx。但 idle 自动认领走的是全局 idle_poll()：

# idle 自动认领走的是全局函数
unclaimed = scan_unclaimed_tasks()
if unclaimed:
    task_data = unclaimed[0]
    result = claim_task(task_data["id"], agent_name)
    if "Claimed" in result:
        wt_info = ""
        if task_data.get("worktree"):
            wt_path = WORKTREES_DIR / task_data["worktree"]
            # 只把路径写进提示消息，没更新 wt_ctx —— 这是隔离缺口
            wt_info = f"\nWork directory: {wt_path}"
        messages.append({"role": "user",
            "content": f"<auto-claimed>Task {task_data['id']}: "
                       f"{task_data['subject']}{wt_info}</auto-claimed>"})
        return "work"

这条自动路径只把 Work directory: ... 写进提示消息，没有拿到队友线程里的 wt_ctx，也没有更新它。

结果是：

idle 自动认领成功
→ 任务 JSON：owner=alice, in_progress, worktree=alice-config
→ messages：告诉模型 Work directory 是 alice-config
→ wt_ctx：仍然是 None
→ _run_bash/_run_read/_run_write：仍以主仓库 WORKDIR 为 cwd

提示里知道目录，不等于工具真的切了目录。 模型如果老实地在参数中使用完整路径，可能看起来能工作；但相对路径 write_file("config.py") 仍可能写回主仓库。

源码里有个路径缺口

修复方向也很明确：让 idle_poll() 不直接调用全局 claim_task()，而是接收一个由队友线程传入的 claim 回调；回调内部完成“claim + 更新 wt_ctx”，和手动路径共用同一函数。这样自动、手动两条入口不会再漏掉目录切换。

还有一个清理边界：_count_worktree_changes() 用 git log @{push}..HEAD 统计未推送提交，但新分支通常没有 upstream；源码没有检查 r2.returncode，这时 stderr 被忽略、commits 可能算成 0。“0 个未推送提交”不一定代表真的检查成功。

真实 CC 分成两条路线。

第一条是当前会话切换。EnterWorktreeTool 创建后直接改变进程 cwd，并保存原目录；ExitWorktreeTool 无论 keep/remove 都恢复原 cwd。它不是给提示词补一句路径，而是修改会话实际目录。

第二条是子 Agent 隔离。AgentTool 在 isolation: "worktree" 时创建临时 worktree，通过 cwdOverridePath 包住子 Agent 的所有执行；主会话 cwd 不变。无改动可自动清理，有改动则返回路径与分支供 review。

真实 CC 没有 Task.worktree 绑定。PersistedWorktreeSession（worktree.ts:756-768）保存 originalCwd、worktreePath、worktreeName、worktreeBranch、originalBranch、originalHeadCommit、sessionId 等字段，再由 saveWorktreeState()（sessionStorage.ts:2883-2920）写入 transcript。

教学版把 task 与 worktree 直接绑在一起，是为了讲清“认领任务后工具换目录”；真实 CC 把任务和 worktree 当两个系统，由会话或 AgentTool 的隔离选项连接。

小结

s18 把并行团队最后一块物理边界补了出来：

  1. 01Task 增加 worktree 字段，但绑定时仍保持 pending。
  2. 02create_worktree() 校验名字，创建独立目录与 wt/ 分支，成功后才绑定和记事件。
  3. 03手动认领成功后，task.worktree → wt_ctx → bash/read/write cwd，相对路径落进独立目录。
  4. 04删除前检查未提交文件和未推送提交；不确定或有成果时默认 keep。
  5. 05当前源码的 idle 自动 claim 没更新 wt_ctx，自动认领后仍可能在主目录执行，这是实质性隔离缺口。

我读到这里的感受是：“任务属于 Alice”是管理信息，“工具运行在 Alice 的目录”才是隔离事实。 两者必须在每一条认领路径上都接通，漏一条自动路径，提示词再清楚也兜不住。

团队现在有任务、通信、协议、自动认领和独立目录了。下一节 s19 会换一个方向：如果每接 Jira、数据库、部署平台都要手写 schema 和 handler，工具代码会无限膨胀。MCP 要解决的是外部工具如何在运行时被发现并接进现有循环。
