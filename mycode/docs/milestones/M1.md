## 1. 目标与范围

### 1.1 M1 的交付定义
"**把 M0 骨架升级成真正贴近 Claude Code 体验的 agent**"——给 loop 添加记忆、短期清单、持久任务、隔离子 agent、可挂 skill、长会话不失败（compact）、分角色模型成本优化。

### 1.2 包含
- **M1-1 Memory**：`memory/` 独立模块 + 体积上限 + `@path/to/file` 单层引用展开 + 循环引用保护
- **M1-2 TodoWrite**：短期 checklist 工具 + `/todos` slash
- **M1-3 持久化 Tasks**：`.mycode/tasks/task_<id>.json` + TaskCreate/Get/Update/List + `/tasks` slash + 级联 unblock
- **M1-4 Subagent Task 工具**：三种 `subagent_type`（Explore/general-purpose/Plan），按类型过滤工具白名单
- **M1-5 Skills**：扫描 `skills_dirs`，按需 `LoadSkill`，frontmatter 解析，同名前者覆盖后者
- **M1-6 Compact + Roles**：`microcompact` 外置 blob、`auto_compact` 摘要、`/compact` + `Compact` 工具、`roles.{main,summarize,subagent}` 分角色模型

### 1.3 **不包含**（明确延后到 M2+）
- 后台任务、MCP 客户端、Session resume → M2
- 多 Agent 协作（teammate 消息总线）、Worktree 隔离 → M3
- `allow/deny/ask` 三态权限、动态模型路由 → M2/M3

## 4. 已知限制

1. **子 agent 无法访问父 agent 的工具上下文**：Task 工具每次调用创建全新的 `AgentState`，子 agent 看不到主 agent 已经 Read 过哪些文件。这是预期行为（隔离），但模型有时需要额外说明。
2. **Compact 工具的"本轮立即结束"语义不显式**：TOOLS.md §5.1 要求调用后 loop 立即结束，当前实现只是替换 messages，依赖 LLM 下轮自然 `finish_reason=stop`。在极端情况下可能连续产生多轮 Compact 调用。M2 可加显式终止信号。
3. **auto_compact 会丢失 tool_calls 结构**：摘要后仅保留 system + 一条 user summary + 尾 6 条，中间轮次的 `tool_calls` ↔ `tool_result` 对应关系落入摘要文本，模型无法再追溯具体调用。
4. **Skills 前缀加载在 `/provider` 切换后不刷新**：切换 provider 后 system_prompt 仍是启动时算的那份，skill 列表不变。目前无刷新需求，但 M2 加更多运行时能力时需留意。
5. **Roles 只能按 provider profile 覆盖，不能调 `max_tokens` / `temperature`**：当前 `RoleConfig` 只含 5 个连接参数；如果 summarize 需要单独调温度，M2 再扩。
6. **`tests/test_compact.py::test_auto_compact_produces_summary` 用 StubLLM**：没覆盖真 LLM 的流式/非流式差异，M1 时间不够做 respx 录制。M2 补。

## 8. 下一里程碑（M2）切入点

M1 完成后,**数据结构已经齐备**(Tasks/Skills/Memory/Compact/Roles 都在),M2 的主要工作是 **连通性 + 持久化**：

1. **Session resume**:`.mycode/sessions/<id>.jsonl` 每轮 append,启动 `--resume <id>` 恢复
2. **BackgroundRun / BackgroundCheck**:在单独线程跑 shell,通知在下轮 loop 注入
3. **MCP 客户端**:按 CONFIG §3.7 启动 stdio/sse/http server,工具清单并入 registry
4. **Slash 命令完整集**:`/resume` / `/sessions` / `/bg`

建议从 **Session resume** 起手——它串起了 Memory/Tasks/Todo 这些已有能力,且 90% 代码是纯 I/O,风险最低。
