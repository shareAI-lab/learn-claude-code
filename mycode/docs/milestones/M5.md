## 3. 关键设计决策

### 3.1 Worktree 为什么用 `workspace_root` 覆盖而不是 `os.chdir`
Python 的 `os.chdir()` 是进程级的，会影响**所有线程** —— 这对我们致命：
- 后台任务线程（`BackgroundRun`）可能正在 cwd 里跑 shell
- 队友线程（`start_teammate_loop`）正在 `.mycode/tasks/` 扫任务
- 一个 `chdir` 打乱所有并行者

所以选择**进程 cwd 保持不变**，只改 `cfg.workspace_root()` 的返回值。所有文件工具通过 `cfg.workspace_root()` 获得基址，老线程仍看旧 cwd（用它的上下文）而新动作看新 worktree。

### 3.2 Worktree 状态持久化到 `.mycode/worktrees/state.json`
原因：启动 `mycode` 时如果发现 `state.json::active == True`，说明用户上次进了 worktree 但没 exit（或 Ctrl-C 掉了）。我们应该把 workspace_root **自动恢复到那个 worktree**，不然用户以为自己在 worktree 里改文件、实际写到了主仓库。

`cli.py::_maybe_resume_worktree` 启动钩子完成这件事。

### 3.3 Worktree 的 ExitWorktree("remove") 脏检查策略
- 有未提交改动 + 未传 `discard_changes=True` → 拒绝，返回 Error（列出脏文件）
- 有未提交改动 + 传了 `discard_changes=True` → `git worktree remove --force`
- 无未提交改动 → 正常 remove + 删分支

**没做**的：基于 merge-base 检测"是否有独立 commit 未合并" —— 实现复杂度高，M5 简化为只看 dirty 状态。如果用户做了本分支提交但没合回 main，remove 会丢这些 commit（分支被 `branch -D`）；留给 M6 加护栏或切换为"默认只 keep"。

### 3.4 MCP E2E 为什么用真实 stdio 子进程而非 stub adapter
- 覆盖 `stdio_client` + `ClientSession.initialize` + `list_tools` 的真实 JSON-RPC 协议交互
- 捕获 SDK 升级导致的行为变化（比如 MCP 协议版本升级）
- 启动 stub 的开销约 500ms，可接受
- 要点：stub 用 `sys.executable` 保证能看到 mcp 包（否则新 subprocess 找不到依赖）

### 3.5 队友 loop 录制用 respx 而非 VCR
- respx 只拦 httpx，恰好 openai SDK 底层就用 httpx
- 设 `side_effect=[resp1, resp2, ...]` 可按序返回多轮响应，契合 "WORK 阶段第 1 轮是 A，唤醒后第 2 轮是 B" 的测试需求
- VCR 需要先"录"一次真实请求 —— 我们想完全控制响应不走真网络

### 3.6 UI 加固不做 Rich Live 的原因
- `Live` 会占领整个渲染区，和现有的流式 text delta 不兼容（流式 print 会把 Live 区域挤走）
- 全换成 Live 意味着重写所有 on_text/on_tool_call 的写入路径
- M5 选择"行内标记增强" —— 耗时后缀 + 图标 + TodoWrite 特化 —— 成本 50 行代码，效果接近 Claude Code 的 80%

### 3.7 PyPI 占用检查为什么不用 API Token
- 只查包名是否存在，`GET /pypi/<name>/json` 匿名即可；404 = 可用，200 = 被占
- 不需要登录，避免 Token 泄漏风险

## 4. 已知限制

1. **Worktree 的 commit 未合检查未做**：在脏分支 remove 只看 working tree 状态，不看 `git log main..HEAD`。极端场景用户会丢 commit
2. **Worktree 与 Session 的交互未验证**：进 worktree 后写 session 会落到 `<worktree>/.mycode/sessions/` 还是主仓库的？当前是前者（`workspace_root` 决定），但没测过 resume 跨 worktree 的行为
3. **MCP E2E 只测了 stdio**：sse / http 传输的 E2E 仍缺（需要 mock HTTP server，比 stdio 复杂一倍）
4. **队友 loop 录制只测简单路径**：模型返 tool_calls → 执行工具 → 返回的多轮对话没完整录制；我们只覆盖"模型直接 stop 进 idle"
5. **UI 耗时显示是 monotonic 差值**：如果回调顺序乱（on_tool_result 没对应的 on_tool_call），会默认为 0ms；非典型路径（如被 interrupt 后补灌 `[interrupted]`）未覆盖
6. **PyPI 未真实推送**：`mycode` 名字已确认可用，但需要 `UV_PUBLISH_TOKEN` 才能 `uv publish`，留给维护者手动执行
